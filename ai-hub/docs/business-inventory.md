## BBの5段階

| Stage | 名称 | 定義 |
|-------|------|------|
| 1 | 下書き係 | AIが下書き、人間が実行 |
| 2 | 実行係 | AIが実行、人間がチェック |
| 3 | 業務担当 | ナレッジをスキル化、AIが丸ごと担当 |
| 4 | 承認つき自動運転 | AIが自律稼働、人間は承認ボタンだけ |
| 5 | 完全自動 | 承認パターンを学習、人間不要 |

---

## スコアリング基準

**頻度 (F)**: 1=年数回 / 2=月次 / 3=週次 / 4=日次 / 5=常時
**工数 (E)**: 1=5分以下 / 2=30分 / 3=1-2時間 / 4=半日 / 5=終日
**ミス許容度 (R)**: 1=ミスOK / 2=軽微 / 3=修正可能 / 4=影響大 / 5=致命的
**自動化優先度 = F × E × (6-R)**（ミス許容度が低い=安全に自動化できる）

## 3. 次にスキル化すべき業務 TOP 5

BBの原則「スキル資産の蓄積差が取り返しのつかない差になる」に基づき、
**スコアが高く、かつ既存インフラと連携しやすいもの**を優先。

### #1: Chatwork/LINE → Slack集約（スコア50）
- **理由**: 入口が分散していると全自動化が不可能。BBの「入口をAIに」の完成
- **工数**: 2-3日
- **技術**: Webhook→Slack API転送
- **依存**: なし（即着手可能）

### #2: 競合モニタリング（スコア60）
- **理由**: 毎日手動で見ている情報収集を完全自動化。ニュースモジュールの延長
- **工数**: 1-2日
- **技術**: RSS + サイト差分検知 + Claude要約
- **依存**: ai-hub newsモジュール（構築済み）

### #3: コンテンツ制作パイプライン（スコア60）
- **理由**: note.com運用が既にあり、X調査→企画→執筆→投稿を一気通貫に
- **工数**: 3-5日
- **技術**: x-trend-research → Claude → note-com-mcp
- **依存**: note-com-mcp（稼働中）

### #4: 週次統合レポート（スコア48）
- **理由**: 全プロジェクトのKPIを週次で自動集計。BBのStage4→5への橋渡し
- **工数**: 1日
- **技術**: ai-hub KPIモジュールの拡張
- **依存**: ai-hub kpi/collector（構築済み）

### #5: 問い合わせ一次回答（スコア36）
- **理由**: メール自動化の延長。FAQ→自動回答→承認のフルフロー
- **工数**: 2-3日
- **技術**: ai-hub mailモジュール + FAQナレッジベース
- **依存**: ai-hub mail（構築済み）

## 5. 注意事項

- **承認データの蓄積が鍵**: Stage 4→5への移行は承認履歴の量に依存。今すぐ全業務を承認フロー経由にすることが最重要
- **コスト管理**: Claude API + Apify + Smartlead で月額$200-500。ROIを週次でトラッキング
- **リスク**: メール誤送信、契約書ミスは許容度が低い。これらは最後までStage 4を維持
- **スキル定義書**: 新しいスキルを作る際は必ず `SKILL.md` を先に書き、ナレッジを構造化する
